# 地图研究工作要求

## 入口与结构

- 地图功能页面是 `railway.html`，经济环境子页面是 `economy.html`；`index.html` 和 `new-railway.html` 仅作兼容跳转。
- 数据写在 `railway-data.js`，交互写在 `railway.js`，样式写在 `style.css`。
- 本目录是独立铁路预研，不得隐式改变 Airport 正式模型的数据、配置或运行结果。
- 经济子页面使用公开合成情景，分局入口自动选中所属经济区；利率为全国基准，PE 是可选参考。分局财务未初始化时不显示虚构收支。静态全样本仅供研究，不作为正式经营或 AI 的未来数据接口。
- 使用 `py map_research/serve.py` 启动带种子生成能力的独立本地服务。seed 为 0—9,007,199,254,740,991 的整数，切换显示筛选不重新生成；相同模型、配置和 seed 必须可重现，基期不随 seed 改变。
- 分局经营研究页为 `bureau.html`，当前东北十二家、华北十家共22家分局已初始化；不得为尚未配置的经济区虚构参数或账目。完整 2025—2085 样本用于校准，和宏观页准确率预测功能分开；总计 61 个点含基期，60 年累计结余只计 2026—2085。每项成本独立计算固定、变动和价格，三项业务与四项投入汇总必须对平。原宏观模型不因切换分局而改变。
- 华北地图外净结算在普通运营收支完成后单独加到货运收入、总收入和结余，不增加站务收入、地图线路或成本。沿用各自分局 freight_index，不新增周期或固定年增速。当前原包基值统一乘0.9；保留100%／90%／80%对照。普通货运量与隐藏等效结算量必须分开显示及导出，freight_tons_10k 仅为普通量，不得将等效结算量回灌工作量或物理运量统计。所有网络视为基期已营业，雄安沿用修订客流基期，无隐藏净结算。
- 当前 V0.3 通过六类预置参数形成不同情景倾向；情景选择、参数、事件与宏观扰动使用独立随机流。保留短长时间前缀一致性，危机与修复计划不因显示年份改变；界面显示情景倾向和当年阶段，不公开完整未来事件计划。预置样本与本地接口须使用相同模型版本。
- V0.3.1 工资需允许持续低迷和危机下的滞后下降，以及需求复苏后的渐进恢复；工资变化通过劳动市场压力和工资水平缺口传递，不每年永久扣减同一损失。原“估值指数”统一展示为“行业 PE 参考指数”，保留底层字段兼容。
- V0.4 地区路径由独立随机流形成，10—22 年阶段及渐进转折；地区倾向影响概率，不固定兴衰命运。客运、货运、工资趋势分别设置，全国利率和 PE 继续统一。地区状态仅展示当年名称，完整路径参数留在生成层；保留共同基期、复现、顺序独立和历史前缀一致。
- V0.5 先将阶段抽取的正客货运目标增长率乘 0.45，负增长不变，再加入全国情景附加项和平滑过渡。提高低迷及成熟阶段的持续性，不强制短期复苏，不设置需求总量硬上限。全国周期、危机和金融路径保留；工资通过原机制内生变化。分局收支在独立 `bureau_model/` 中计算，不按年份固定提效。
- 经营 V0.3 人工使用原始地区工资倍数 × 截至当年工资高点倍数的 −θ 次方，高点至少为 100。高速／普速／站务 θ=0.35／0.22／0.18，逐年维护高点、工资回落不撤销调整，不叠加原 wage_price_beta。历史工资弹性只用于 V0.2 对照。不得因此修改宏观或运量路径；隐含等效用工仅为后台诊断。页面区分 A/B/C 与当前 Seed，96 Seed 报告须与运行版本和配置哈希匹配。
- 预测仅限单一区域和单一指数，可设置起始年、2／5／10 年期限、期望准确得分；每次生成允许不同结果，切换显示和悬停不重新随机。图上显示预测中位虚线，预测时点后未发生的真实值不得作为实际曲线提前展示；样本推进到预测结束后再显示实际得分。当前研究页面用完整样本生成，正式游戏须迁移到服务器。
- 预测评分按期限映射误差，再按同一尺度回算；80 分的 2／5／10 年平均年度偏差分别约 2.5%／5%／8.5%，保留约 ±4 分随机浮动。100 分逐年完全准确。单年极端误差有上限，面板与回测同时展示偏差；不得继续使用“得分 = 100 − 平均百分比误差”的旧尺度。

## 数据维护

- 当前网络只建模站点和两站间的连接，不维护整条线路的命名分组。
- `stations` 登记 `{ id, name, lat, lon, city, region }`；同一实体车站复用 ID，不同实体的同名站不应仅凭名称合并。
- `connections` 登记 `{ id, from, to, type }`；每条连接恰好引用两个存在且不同的站点。
- 连接无方向，同端点同类型只保留一条；高速与普速并行连接分别保留。
- 连接 ID 使用 `类型:排序后的端点ID|端点ID`，保证反向录入不会增加重复连接。
- 新增连续站点列表时，只连接相邻站点；删除粗略直连段后，不得自动重新补回。
- 经度使用 `lon`，纬度使用 `lat`，按用户提供的小数精度录入。
- 类别为 `high_speed` 或 `conventional`，沿用用户的研究分类。
- 统一展示整个泛中国路网，不设置区域筛选；站点的区域元数据不限制连接展示。
- 数据或界面变化后更新页面资源版本，避免浏览器沿用缓存。

## 界面与验证

- 左侧只保留分局列表和按分局／所属站点搜索，不生成全网连接／站点大列表；保留高速／普速地图筛选、缩放与平移。
- 选中连接展示两个端点，选中站点展示直接相连的站点及对应连接类型；所属分局管辖网参与集体高亮。
- 站名自动避让，被选中的站点和连接端点优先显示。
- 数据重构比较完整站点和连接集合，检查 ID 唯一性、端点引用、自连接、重复连接及 JavaScript 语法。
- 界面变化验证筛选、搜索、点选、缩放、重置及响应式布局。
- 文档不重复抄写全部连接数据，以 `railway-data.js` 为唯一数据来源。

## 铁路分局公司

- 分局登记在 `railway-divisions.js`，通过一个或多个中心站与交界连接定义归属，与物理站点／连接数据分开维护。路网不连通时可用多个中心定义同一家分局。
- 交界位于连接两站经纬度的中点，仅内部一半归该分局；不删除或切断实际连接，不将交界虚增为站点。
- 从中心站遍历相邻连接，在指定交界停止。每处交界必须分隔一个内侧站和一个外侧站；存在绕行、缺失交界或重叠时，不得标为已划定。
- 地图平时保留高速／普速原色，不叠加分局专色或交界标记。点击分局内站点或连接时，整体高亮管辖网及内侧半段；关闭详情或点击空白处取消高亮。
- 分局列表可定位管辖网；分局概览显示站点数、高速里程和普速里程，以及已登记的站商和站城资产投资开放名单，不展示中心站、范围说明、交界或全体站点列表。地图点选的站点／连接详情独立显示；高速／普速筛选不影响归属计算。
- 站商资格以分局配置中的 `commercialStationIds` 为准，按游戏设计名单手工登记，不凭车站规模、基础服务或站城投资机会推断；不设置商业等级。
- 当前站商名单统一按已确定资格展示，不设置候选分类。
- 站城资产投资站点统一登记在 `stationCityInvestmentIds`，分局概览显示“可开放站城资产投资”，不设置重点或储备分类；与站商资格分开登记。
