# IMPORTANT: City Airport Valuation And Forecast Model Guide

这份文档记录城市机场估值、预测、商业销售预测和合同签约模型的总草案。北京估值 / 预测 v0.1 已经有代码实现；合同签约模型仍处在设计阶段。

真实 source of truth 以后应逐步落在：

- `airport/macro_layers/city_airport_valuation_forecast_layer_sim.py`
- `airport/config/city_airport_valuation/beijing_airport_group_valuation_forecast_v1.json`
- `airport/output/city_airport_valuation/`
- `airport/web/pages/beijing_airport_operations_viewer.html`

## 核心原则

真实经营路径和游戏内预测模型必须分开。

真实经营路径回答：

```text
这条 seed 下实际发生了什么？
```

游戏内预测模型回答：

```text
玩家在当时、只凭历史数据和当时宏观信号，合理能预期什么？
```

合同签约和估值都应读取预测模型，而不是偷看真实未来。真实未来只用于后续验证预测误差、合同输赢和玩家决策后果。

## 当前边界和待解决问题

北京估值 / 预测 v0.1 已经实现独立输出层：

```text
airport/macro_layers/city_airport_valuation_forecast_layer_sim.py
airport/config/city_airport_valuation/beijing_airport_group_valuation_forecast_v1.json
airport/output/macro_runs/<run_id>/<variant>/city_airport_valuation/<region>/<market>_valuation_forecast_seed_sweep.csv
```

它已经接入 `macro_run_orchestrator_sim.py`，在季度经营和财务状态之后自动生成。合同报价模型还没有独立实现；现有商业合同仍由季度经营层里的合同占位逻辑处理。

这些问题对不同模块的影响不同：

- `as_of_year` / `as_of_quarter` 是预测、估值和合同的共同边界。任何预测、估值、合同报价都只能读取该季度及以前的数据，不能读取同一 seed 在未来已经生成的真实经营结果，也不能读取玩家当时不可能知道的后续历史岔路。
- 自由现金流口径主要影响实验性估值观察。当前单人游戏阶段的主估值采用净资产口径；DCF 观察值只用于检查经营现金流、宏观环境和未来估值系统的接口。
- 债务状态进入估值是正常的。正式债务、玩家新增债务和估值压力测试债务都可以被估值模型读取；区别只在于它们属于正式经营状态还是测试/情景标签。
- 合同模型暂时不直接受 DCF 口径影响，但会受 as-of 预测、宏观风险、债务压力和机场议价能力影响。后续合同报价不能直接拿真实未来销售额做保底。
- 当前北京财务层没有分红、上缴、回购或现金再配置机制，因此长期经营会积累大量账面现金。估值层会把 `EV`、`net_debt` 和 `equity_value` 分开输出；若股权价值后期主要由现金抬高，应优先检查资本配置规则，而不是把 DCF 现金流重复削弱。

建议每一条估值或合同输出都显式写入：

```text
as_of_year
as_of_quarter
forecast_horizon_quarters
data_cutoff_quarter
forecast_model_version
valuation_model_version / contract_model_version
```

## 总体分层

建议拆成六块。

### 1. 真实经营路径

这部分已经大体存在：

```text
全球宏观
  -> 区域宏观
  -> 区域航空需求 / 供给
  -> 城市机场客流
  -> 城市机场季度经营
  -> 财务状态 / 资产负债表
```

它输出真实发生的客流、收入、成本、商业收入、capex、债务、现金、折旧和利润。

当前接入状态：

- `macro_run_orchestrator_sim.py` v0.5 已经能把北京样板从宏观、12 种核心历史岔路一路跑到城市机场客流、季度经营和财务状态。
- 其它城市目前只自动跑到城市机场客流层；如果没有季度经营配置和财务配置，会在 run 输出里记录跳过原因。
- 后续扩展其它城市时，应先补季度经营配置，再补财务状态配置。

估值模型不直接改变真实路径。它只读取已有输出，给玩家一个“当前公司值多少钱”的口径。

### 2. 游戏内预测模型

预测模型是估值和合同的共同底座。

预测模型必须是 as-of 模型：

```text
forecast(as_of_year, as_of_quarter)
  只能读取 as_of_quarter 及以前的真实历史
  可以读取当时已经发生和已经观察到的宏观 / 区域 / 城市状态
  不得读取 as_of_quarter 之后的真实经营结果
```

这条规则不仅约束估值，也约束免税和奢侈品合同报价。合同报价本质上是“运营商在签约时能如何预测未来销售盘”，不是对真实未来销售额的回放。

输入：

- 过去若干年真实历史。
- 当前年份的宏观、区域航空和城市机场状态。
- 当前机场容量、资产年龄、感知品质、拥挤度。
- 当前合同、债务和资产负债表。

不能输入：

- 当前年份之后的真实未来经营结果。
- 当前 seed 已经生成但玩家不可能知道的后续宏观事件。

第一版预测窗口建议：

```text
短期预测：未来 5 年
中期预测：未来 10 年
```

预测可以输出：

- 预测客流。
- 预测航运收入 / 成本 / 结果。
- 预测自营商业收入 / 成本 / 结果。
- 预测免税销售额。
- 预测奢侈品销售额。
- 预测经营利润。
- 预测自由现金流。
- 预测资产负债率和债务服务压力。

第一版可以用“历史趋势 + 当前宏观信号 + 城市长期偏置 + 保守误差带”生成，不需要先做复杂机器学习。

北京 v0.1 当前采用的就是这个朴素口径：

```text
历史季度经营 / 财务状态
  -> 最近 4 季度年化基准
  -> 最近 8 季度同比趋势
  -> 当前宏观压力和历史岔路状态修正
  -> 未来 5 年收入、经营结果、维护性 capex 和 FCFF
```

它每个 as-of 季度输出一行估值结果，不读取 as-of 之后的真实经营结果。

### 城市潜在客流预测

城市潜在客流预测应先于经营预测、商业合同和估值成熟。它的详细设计放在：

```text
airport/docs/airport_operations/City_Airport_Potential_Passenger_Forecast_System_Plan.md
```

第一版采用“隐藏真实曲线降质”的方式，而不是再造一个复杂历史外推模型：

```text
隐藏真实潜在客流曲线
  = city_airport_market_demand 已经按 seed 生成的城市长期潜在客流路径

玩家可见预测曲线
  = 隐藏真实潜在客流曲线的降质版本
  + 预测滞后
  + 预测误差
  + 区间带
  + 解释标签
```

这是一种有意设计的游戏内市场研究机制。普通预测不能直接展示隐藏真实曲线，只能按预测等级输出区间、趋势和可信度；下游经营预测、合同和估值只能读取玩家可见预测，不得直接读取隐藏真实未来。神级预测例外，但它必须被定义为 `future_peek_mode = true` 的未来透视 / 开挂模式，而不是普通预测模型的高级版本。

预测等级暂定：

| 等级 | 玩家理解 | 机制边界 |
|---|---|---|
| 初级预测 | 粗略行业报告 / 市场共识 | 普通预测，连续窗口 6 年，短期可用，seed 捕捉弱，容易被现实排名和近期趋势锚定 |
| 中级预测 | 内部研究 / 基础研究 | 普通预测，连续窗口 8 年，能部分识别城市势能 |
| 高级预测 | 高质量咨询预测 | 普通预测，连续窗口 10 年，中心值和方向更可靠 |
| 专业级预测 | 顶级机构 / 专业研究 | 普通预测上限，连续窗口 12 年，仍保留明显误差和区间 |
| 神级预测 | 上帝视角 / 开挂报告 | 质量分固定 100，未来透视，可接近或显示隐藏真值 |

内部只在 `forecast_quality_score = 0 - 70` 内连续插值，控制 `seed_signal_capture_pct`、`forecast_error_band_pct`、`forecast_lag_years` 和可显示的精确预测窗口。`71 - 99` 不作为普通预测空间。神级预测固定为 `100`，走单独的未来透视分支，不进入普通平衡，但可以作为玩家主动开挂或开发调试工具保留。

公开共识预测可以作为默认市场来源，但应单独保留 `forecast_report_source = public_consensus`。它不固定等于低分；有时只是现实排名、近期增长和市场叙事的外推，有时也可能碰巧达到 40-50 分水平。它会影响资产交易价格、合同预期、融资态度和对手决策。因此它是市场预期基准，而不是客观真理。

普通预测区间也不能被写成“真实值正负误差”。`forecast_mid` 是报告模型自己的估计，不是真实曲线；`forecast_low` / `forecast_high` 可以不对称，隐藏真实值不应默认等于区间平均值。可见区间宽度和报告自信程度也不能直接暴露真实质量：低分报告可以很自信但中心值偏离，高分报告也可以更谨慎但更准。同样质量分的报告还可以因为 `forecast_bias_direction` 不同而分别偏乐观或偏悲观。

普通机构报告应保持短中期连续预测口径，不把 20-30 年年度数字包装成严肃市场研究。当前北京样板里，初级 6 年，中级 8 年，高级 10 年，专业级 12 年；更长全周期只属于神级未来透视、沙盒或调试用途。

预测层同时输出事后审计分 `realized_report_quality_score`。它是报告输出后对比隐藏真实 seed 曲线得到的 0-100 分，不等于 `forecast_report_tier`。下游若要模拟机构声誉、交易信任度或商业情报质量，应优先参考审计分和偏差标签，而不是只看报告等级。

## 商业销售预测

商业销售预测用于两件事：

1. 估计未来商业收入。
2. 给免税和奢侈品合同报价提供预测销售盘。

### 自营餐饮零售

自营餐饮零售不建议作为玩家高频操作项。它是机场集团自营盘，用来表达餐饮、普通零售、便利、伴手礼和部分电子旅行消费。

预测公式草案：

```text
自营销售收入预测
  = 预测客流
  * 客群消费权重
  * 区域消费倾向
  * 城市商业效率
  * 机场感知品质乘数
  * 拥挤修正
  * 宏观消费修正
```

自营成本预测：

```text
自营成本
  = 自营固定成本
  + 旅客服务成本
  + 销售成本
```

第一版估值里，自营盘可以直接按预测经营利润进入现金流，不需要单独签合同。

### 免税销售额

免税销售额应绑定真实客流和客群结构，不能只靠消费倾向指数。

预测公式草案：

```text
免税销售额预测
  = 预测有效旅客
  * 人均免税消费基准
  * 免税消费倾向
  * 国际 / 长途 / 中转暴露
  * 汇率和价格吸引力
  * 机场感知品质乘数
  * 宏观消费修正
```

免税销售额是运营商销售盘，不等于机场收入。机场收入来自合同保底和分成。

### 奢侈品 / 精品销售额

奢侈品销售额应比免税更敏感：

- 更受高端商务客、长途客、中转客影响。
- 更受消费信心、资产价格、汇率和机场品质影响。
- 在低景气时应更容易下滑。

预测公式草案：

```text
奢侈品销售额预测
  = 预测有效旅客
  * 人均奢侈品消费基准
  * 奢侈品消费倾向
  * 高价值客群权重
  * 宏观财富 / 消费信心修正
  * 机场感知品质乘数
  * 拥挤和施工修正
```

## 合同签约模型

合同签约模型服务于免税和奢侈品 / 精品两块。餐饮零售第一版不进入玩家合同操作。

### 合同类型

第一版保留两类：

```text
revenue_share
minimum_guarantee_plus_share
```

流水分成：

- 高景气时弹性更强。
- 机场承担下行风险。
- 适合玩家看多未来客流和消费。

保底 + 分成：

- 下行更稳。
- 分成比例通常较低。
- 适合现金流稳定和债务压力较高时。

### 合同报价输入

合同报价不应直接读取真实未来，而应读取预测模型：

- 未来 5 年预测销售额。
- 销售额波动风险。
- 机场感知品质。
- 城市机场客流规模。
- 国际 / 长途 / 高端客强度。
- 当前宏观风险。
- 机场集团议价能力。
- 运营商风险偏好。
- 当前资产负债率和债务服务压力。

债务压力不直接决定合同收入，但会影响机场集团的风险偏好和谈判取向。例如高杠杆状态下，玩家可能更偏好保底合同；运营商也可能因为机场现金压力较大而压低保底或要求更低分成。第一版可以先把它作为合同风险标签和接受分数修正项，而不是复杂谈判系统。

### 合同报价输出

每个合同方案至少输出：

- 合同周期。
- 合同类型。
- 预测销售额。
- 分成比例。
- 保底收入。
- 保底覆盖率。
- 机场预计收入。
- 运营商预计利润空间。
- 合同风险标签。

合同周期第一版仍建议 `5` 年。

### 合同接受逻辑

后续需要避免玩家把所有条件都拉满。

第一版可以用一个接受分数：

```text
contract_acceptance_score
  = 预测销售吸引力
  + 机场规模和品质
  + 客群匹配
  - 保底压力
  - 分成压力
  - 宏观风险
```

如果分数过低，合同不可签或需要降低保底 / 分成。

## 估值模型

估值模型 v0.5 暂时封装为净资产主口径。当前阶段预测、商业合同、资本配置、城市横向比较和龙头地位评分都还没有成熟，若把 DCF 或市场化估值作为主定价，容易让估值看起来比上游系统更聪明。因此主估值先按资产负债表定价，市场化 DCF 只保留为观察值。财务层使用 25% 企业所得税、季度预缴、Q4 年度汇算和 5 年亏损结转后，税后留存收益会自然进入净资产主估值。

```text
主股权价值 Primary Equity Value
  = 账面所有者权益 / 净资产

主企业价值 Primary EV
  = 主股权价值
  + 净债务

P/B
  = 主股权价值 / 账面所有者权益
  ~= 1.0x
```

这个口径的目标不是模拟成熟股票市场，而是给玩家一个稳定、可解释、不会过早依赖未来预测的公司价值锚。现金、债务、贷款压力仍然通过净债务和资产负债表进入价值；经营利润、ROE、P/E、DCF EV 作为诊断指标，不决定当前主估值。

原 v0.3 三层估值保留为实验性观察：

```text
实验经营 EV Experimental Operating EV
  = 未来企业自由现金流 FCFF 折现
  + 保守终值
  + 资产质量调整
  + 商业合同质量调整

实验市场 EV Experimental Market EV
  = Experimental Operating EV
  * 市场估值乘数

实验股权价值 Experimental Equity Value
  = Experimental Market EV
  - 净债务
```

Experimental Market EV 会继续记录市场环境：

- 利率环境：当前 10Y 收益率高于中性值时折价，低于中性值时溢价。
- 信用环境：HY spread 扩大时折价，收窄时小幅溢价。
- 股票市场估值水位：若上游传入 `input_equity_valuation_pe`，会相对中性市场 PE 形成折价/溢价。
- 权益市场情绪：若上游传入 `input_equity_return_pct`，会作为股票市场风险偏好代理；它和 PE 水位分开，避免把“估值贵/便宜”和“当期市场涨跌”混在一起。
- 历史分岔状态：`watch` 和 `occurred` 会给市场层折价，但不直接把经营终值硬砍成另一家公司。

这些实验值不作为当前单人阶段的主估值，也不应被用作最终结算或玩家目标。等预测、商业合同、资本配置、横向比较和 franchise premium 成熟后，再回到 Forward EV / Market EV 的正式估值系统。

### DCF 观察口径

实验 DCF 可以使用 5-10 年预测自由现金流。

```text
企业价值
  = 未来现金流折现值
  + 终值
```

第一版企业自由现金流建议：

```text
FCFF
  = 航运经营结果
  + 自营商业经营结果
  + 合同商业经营结果
  + 折旧摊销
  - 维护性资本开支
  - 税费 / 其它经营调整
```

注意当前季度经营层的 `period_operating_profit_million_cny` / `quarter_operating_profit_million_cny` 是折旧前经营结果。因此北京 v0.5 的实验 DCF 观察值实际计算 FCFF 时，不再机械加回折旧，而是：

```text
FCFF v0.1
  = 预测折旧前经营结果
  - 预测维护性 capex
  - 25% 简化现金税费 / 其它经营调整
```

折旧仍然用于估算维护性 capex 和资产质量，但不重复加回到经营现金流里。

如果使用 FCFF，现金流里不要扣利息、不要扣还本，也不要加新借款；债务统一在估值末端通过净债务扣除。否则会把负债惩罚两次。

股权自由现金流 `FCFE` 可以作为后续扩展，但不建议第一版主用：

```text
FCFE
  = 经营现金流
  - 利息
  - 还本
  + 新借款
  - capex
```

FCFE 对融资结构和再融资假设非常敏感，早期容易让估值结果被贷款节奏牵着走。

折现率可以来自：

- 区域长期利率。
- 宏观风险溢价。
- 城市发展强度不确定性。
- 机场资产年龄和施工风险。
- 公司资产负债率。

终值增长率应保守，尤其在血战到底模式下不能无限膨胀。

### 资产净值参考

机场是重资产行业，资产净值应该作为估值锚。当前单人游戏阶段，为了让估值足够稳定、不过度依赖未成熟的预测和合同模块，主估值先机械锚定账面净资产；未来正式市场化估值再把资产质量、龙头地位、商业合同预期和资本配置作为溢价/折价来源。

```text
资产质量调整
  = 固定资产账面净值
  * 资产质量折扣 / 溢价
```

影响因素：

- 航站楼年龄。
- 剩余折旧年限。
- 容量是否匹配城市需求。
- 感知品质。
- 是否存在大额未来翻新 / 重建压力。

### 商业合同质量调整

长期、稳定、高保底、高分成的合同应提高估值。

```text
商业合同质量
  = 合同剩余年限
  + 保底稳定性
  + 分成弹性
  + 预测销售增长
  - 合同下行风险
```

合同质量不应直接替代现金流，而应作为倍数或折现率的修正。

### 净债务

```text
净债务 = 短期债务 + 长期债务 - 现金
当前主股权价值 = 账面所有者权益
当前主企业价值 = 当前主股权价值 + 净债务
```

如果现金大于债务，净债务为负，会增加股权价值。但第一版可以设置现金折扣，避免超大现金余额让估值过度膨胀。

债务进入估值是正常机制，不应被排除。需要区分的是债务的用途和标签：

```text
正式开局债务：进入正式估值
玩家新增债务：进入正式估值
测试贷款 / 压力测试贷款：进入情景估值或压力测试估值
```

北京当前用于验证贷款机制的几笔贷款可以保留为估值压力测试材料。估值层可以同时输出：

```text
operating intrinsic valuation
market valuation adjustment
reported financial state equity valuation
loan stress active tags
difference attribution
```

当前 v0.1 读取财务状态层的 reported path，因此北京配置里的测试贷款会自然进入估值。这样可以检查模型是否正确反应贷款发生、现金增加、capex 消耗、资产形成、资产负债率上升和还本付息压力。若单纯借款导致企业价值大幅跳变，通常说明 DCF 口径或净债务处理存在重复计算。

- 当前估值。
- 企业价值。
- 股权价值。
- 净债务。
- 预测 5 年自由现金流。
- 折现率。
- 终值。
- 商业合同质量。
- 资产质量。

- 奢侈品合同方案。

- 分成弹性和上行空间。

## 与血战到底模式的关系

血战到底模式不应只看最终一年估值。

更合适的方式是：

- 每个季度或每年都可以计算当前估值。
- 长期模式下玩家目标是持续经营、维持现金、避免资产老化和债务失控。
- 估值模型应反映当前公司状态，而不是无限期末结算。
- 城市发展强度在不同 seed 下变化时，估值应跟随城市命运变化。
