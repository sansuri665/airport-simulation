# 整理完成后的界面合并计划

## 目的

本文只记录 `airport` 完成当前修整与重构之后的界面合并方向，不属于当前阶段的实施任务。

当前优先事项仍是完成运行入口、数据安全、前后端边界、文件拆分和回归测试。上述工作稳定前，不提前合并页面，也不借合并修改模型公式或运行结果。

## 当前页面关系

### 北京机场经营 Viewer

`beijing_airport_operations_viewer.html` 是较早形成的只读汇总页面，主要展示：

- 经营损益。
- 客流与容量。
- 资产折旧和资产负债表。
- 全周期年度或季度轨迹。
- 估值曲线。

其中多数经营历史能力已经被 Seed Explorer 的“北京运营”覆盖，而且动态测试中的经营报告、项目、合同、融资、服务质量和商业板块信息更加完整。

估值虽然仍存在于静态页面中，但当前还不能作为正式可用的游戏功能。因此，估值暂时不构成长期保留独立“机场经营 Viewer”的理由。

### 有效客流预测 Viewer

`beijing_potential_passenger_forecast_viewer.html` 当前独立展示不同预测等级和报告期的潜在客流、航司供给与有效客流预测。

它本质上是玩家经营过程中可获得的信息和判断工具，更适合成为动态经营界面中的“预测”部分，而不是长期保持为单独的主入口。

### Seed Explorer / 动态测试

动态测试已经同时承载：

- 城市市场和完整 Seed 运行。
- 北京机场经营历史。
- 季度推进。
- 经营、财务和各商业板块报告。
- 项目、合同与融资操作。
- 玩家存档。

因此它更适合作为未来统一的机场经营主体界面。

## 整理完成后的目标

未来将“北京机场经营”和“有效客流预测”合并进动态测试，形成一个统一的机场经营界面，至少包含：

1. **总览**：经营历史、财务、客流容量、服务质量、设施项目、债务融资、合同和商业板块。
2. **预测**：有效客流预测、预测等级、历史报告和预测与实际结果对照。
3. **经营事务**：项目、合同、融资等玩家操作。
4. **季度推进与存档**：继续作为动态模拟的时间和状态主线。

合并后：

- 动态测试逐步改名为正式的“机场经营模拟”或类似名称。
- 原独立机场经营 Viewer 和有效客流预测 Viewer 不再作为首页主入口。
- 两个旧页面可以暂时保留为开发调试、数据核对和回归验证工具，确认统一页面稳定后再决定是否删除。

## 实施前提

只有在以下整理工作基本完成后才开始合并：

- 统一启动入口稳定。
- 固定 Seed 回归测试稳定。
- Viewer/API 数据边界和 Schema 明确。
- Seed Explorer 大文件已按职责拆分。
- 经营历史和预测数据可以按需加载。
- 玩家只能看到当前季度允许获得的历史和预测信息。

## 本计划不包含

界面合并本身不负责：

- 重做估值模型。
- 修改客流预测算法或预测等级规则。
- 修改经营、财务、项目、合同和融资公式。
- 改变随机数消费顺序或现有固定 Seed 结果。

这些内容如果需要调整，应另行设计和验证，不能与界面合并混在同一次修改中。
