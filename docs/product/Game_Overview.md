# Airport 游戏总体介绍

这是一篇面向玩家的第一读物。它说明你在游戏里扮演谁、面对怎样的世界、每个季度能做什么，以及当前版本做到哪里；参数和代码细节留在相应的专题文档中。

## 一句话认识这款游戏

你经营的是一家具备真实资产、长期合同和债务压力的机场集团：先在不完整的信息中判断未来客流，再通过航站楼工程、商业合同和融资安排，让机场在增长、拥堵与宏观周期中持续运转。

当前可操作样板是**北京机场集团**。全球宏观、区域航空和中国大陆城市市场共同构成本局外部世界，北京机场的经营与财务结果会随这些外部条件和你的行动变化。

## 你扮演谁

你扮演北京机场集团的经营决策者，而不是飞行员、航司经理或城市规划部门。你不能直接命令旅客出行，也不能凭空增加航班；你能管理的是机场集团自身可以控制的事项：

- 观察市场需求、航司供给和机场容量；
- 决定商业合同是否续签；
- 翻新、新建、拆除或重建航站楼设施；
- 安排贷款，平衡现金、建设支出和债务压力；
- 推进季度，并从后续报表检验判断是否正确。

因此，游戏的核心不是追求单一最高客流，而是在需求、容量、服务质量、现金和负债之间做长期取舍。

## 每一局世界如何产生

每局由一个 **Seed（随机种子）**决定。同一个 Seed 在相同版本和配置下，会产生同一条世界线；换一个 Seed，就可能遇到不同的增长、通胀、利率、航空需求和供给变化。

世界大致按下面的顺序形成：

```text
全球经济
  -> 各区域经济与航空市场
  -> 中国大陆城市需求和航司供给
  -> 北京机场能够承接的客流
  -> 机场经营、合同、项目、债务与财务结果
```

这些外部变化不是玩家直接控制的背景数字。经济环境会影响客流和融资成本；航司供给不足时，再强的出行需求也不会全部变成机场吞吐；航站楼容量不足时，已经形成的有效需求仍可能无法被机场承接。

想进一步理解各层怎样连接，可阅读[模型主链](../models/Model_Pipeline.md)。

## 真实客流不等于你看到的预测

游戏中需要区分三件事：

| 内容 | 含义 | 对经营结果的作用 |
| --- | --- | --- |
| 真实市场路径 | 本局实际发生的城市需求与航司供给 | 决定真实经营环境，但未来不应被玩家直接知道 |
| 有效客流预测 | 报告机构根据有限信息作出的判断 | 帮助决策，可能存在滞后、偏差和区间误判 |
| 机场实际吞吐 | 有效需求再经过机场容量等约束后的结果 | 进入机场收入、成本和服务质量计算 |

“有效客流”本身也不是所有想出行的人数，而是城市潜在需求与航司可提供运力共同允许形成的客流。机场最后能接住多少，还要看设施容量。

所以预测报告的价值在于降低不确定性，而不是替你揭晓未来。高等级报告通常视野更长、质量更好，但普通报告不保证一定准确。预测机制详见[航空与城市机场市场](../models/Aviation_and_City_Market.md)。

## 一局的时间线

- **2025–2029 年**：开局经营历史。你可以查看这些已经发生的客流、收入、成本和合同基准，但不能改写它们。
- **2030 Q1 起**：玩家接管经营。机场经营、财务、合同、项目和贷款以季度为节奏结算。
- **长期世界线**：进入模拟经营时，系统会准备足够长的外部世界，让项目、合同和债务的长期影响能够继续展开。

开始时，你先在首页的统一 Seed 中心创建或激活一条 `Seed + 年数` 世界，生成所需缓存，再从固定上下文入口进入北京机场的“模拟运营”。普通经营使用 60 年槽位；“加载历史”用于只读回放，不接受玩家经营动作。

## 每个季度做什么

一个季度可以按下面的节奏理解：

1. **阅读报表**：先看客流、容量、服务质量、商业收入、现金和债务发生了什么。
2. **识别问题**：判断当前瓶颈来自市场需求、航司供给、机场容量、施工影响，还是财务压力。
3. **作出行动**：在开放条件允许时处理合同、设施项目或融资。
4. **推进季度**：让已提交的行动进入后续经营和财务计算。
5. **复盘结果**：比较预期与实际变化，再决定下一步。

保存游戏时，系统保存当前季度和你的行动记录；再次读取时，会用同一世界线和行动恢复经营状态。更具体的点击顺序和限制见[当前游戏流程](Game_Flow.md)与[界面使用指南](../getting_started/User_Guide.md)。

## 当前能做的经营动作

### 合同

当前主要处理免税和奢侈品合同。合同临近到期时会开放下一周期的建议条款，你可以确认或暂缓；超过期限仍未确认时，系统会自动续签。现阶段不能自己修改分成率、选择多个合作方或展开谈判。

### 项目

你可以根据槽位状态翻新、新建、拆除或拆除重建航站楼。不同工程会影响施工期容量、现金支出、资产形成和后续折旧；已确认的工程当前不能取消。

### 融资

你可以选择短期周转贷款、长期建设贷款或带宽限期的建设贷款。利率会受宏观环境、期限、信用压力和杠杆影响。贷款并不会自动与某个项目绑定，建设和还债所需的现金时点需要自行安排。

这些动作怎样进入财务账本，详见[财务、合同与项目](../models/Finance_Contracts_and_Projects.md)。设施容量和服务机制详见[机场季度经营](../models/Airport_Operations.md)。

## 主要报表怎么看

经营界面把同一套季度结果分成若干观察角度：

| 报表 | 主要回答的问题 |
| --- | --- |
| 经营总览 | 本季度最重要的经营与财务变化是什么 |
| 客流与容量 | 需求从哪里来，航司和机场各自卡在哪里 |
| 服务质量 | 航站楼年龄、拥挤和施工怎样影响旅客体验与商业表现 |
| 航空与商业 | 航空业务、餐饮零售、免税和奢侈品贡献多少收入与成本 |
| 设施与项目 | 各槽位处于什么状态，工程怎样改变容量和资产 |
| 债务与融资 | 贷款如何提款、付息和还本，杠杆是否过高 |
| 财务分析 | 利润、现金流、资产、负债和所有者权益是否可持续 |

年报、半年报和季报只是把已经发生的季度按不同周期汇总，不会改变世界线或重新生成结果。

## 目前怎样算赢或输

当前版本**没有正式的通关、破产结算或统一分数**。现金可以降到负数并触发警告，但尚不会自动结束游戏；估值也只是观察指标，不能用于交易或胜负结算。

现阶段更适合把一局看作长期经营沙盘，并自行设定目标，例如：

- 在不发生严重拥堵的前提下承接增长；
- 避免项目集中导致现金断裂；
- 控制债务，同时维持设施质量；
- 判断一份预测是否值得相信，并检验长期决策；
- 比较不同 Seed 下同一种经营策略的表现。

正式胜负条件、交易和更完整的商业博弈仍属于未来设计，见[项目路线图](../plans/Roadmap.md)。

## 动态经营与 Viewer 有什么区别

当前首页的页面承担不同用途：

- **首页统一 Seed 中心**负责创建、激活、生成和安全删除 `Seed + 年数` 槽位，并为四个页面生成固定上下文入口。
- **Seed 动态测试**是主要经营环境。它使用首页选定的固定世界，允许读取或重建缓存、进入北京模拟运营、提交行动、推进季度和保存进度。
- **全球宏观 Viewer**用于只读观察本局外部经济环境。
- **城市航空市场 Viewer**用于比较 47 城并查看所选城市的长期潜在客流、航司供给和五类客群分配，不提供 47 城合计，也不展示机场经营承接与容量。
- **北京客流预测 Viewer**默认展示玩家报告叙事、修订与六种客流口径；开发审计需单独切换后才加载真实结果和评分。

Viewer 里的完整历史不等于玩家角色在当时拥有全部未来信息。它们目前主要是模型观察和分析工具；北京的季度经营历史与行动应在动态经营界面完成。未来计划是把经营总览、预测信息和经营事务逐步整理到更统一的正式界面中。

## 当前北京样板与尚未实现的边界

当前全球、区域航空和中国大陆多城市市场都参与世界生成，但只有北京形成了较完整的季度经营闭环。因此：

- 北京的初始设施、客流结构、商业能力、财务状态和合同不能直接代表其它城市；
- 其它城市尚没有北京同等完整的经营、项目、合同、融资和财务操作界面；
- 当前没有机场买卖、并购、上市、分红、股权融资、多人竞争或 AI 对手；
- 合同没有合作方竞标，项目没有承包商、随机超支和施工事故，贷款也没有银行竞价；
- 客流预测与机场经营仍是两个入口；预测数据已经分离玩家与开发审计，但经营接口仍需收窄完整未来季度信息；
- 估值功能尚未成为成熟的玩家决策和交易系统。

如果要把北京样板扩展到新城市，应先阅读[北京模板与新城市配置指南](../reference/Beijing_Template_and_New_City_Guide.md)，不要直接复制北京数值。
