## 2. 区域与城市数量边界

- 区域航空层的百万人次改为明确的 reference-only 解释；它用于区域压力诊断，不再被误当作 47 城城市客流总量包络。
- 城市潜在客流以城市自身配置为体量锚，宏观、区域航空环境、城市弹性、长期收敛和 Seed 分岔共同决定发展路径。
- 总量和商务、休闲、长途、中转、探亲访友五类结构分开建模，分项在城市总量内严格守恒。
- 不同 Seed 继续保留不同区域、城市和客群的发展风格；公共模板定义共性，城市配置只表达有依据的差异。
- 旧的指数上下界保留为极端输入安全线，同时发布 raw、final、边界方向和连续命中年数，便于识别长期截断。

## 3. 航司供给与机场承接

城市客流现在保留四个互不混淆的权威口径：

```text
城市潜在需求
→ 航司计划投放 offered
→ 需求封顶后的可承接供给 serviceable
→ 机场容量约束后的最终吞吐 served
```

- 航司供给使用独立年度状态、长期均衡、需求缺口追赶、区域短期规划和 Seed 阶段事件，不再是固定正弦波或潜在需求的机械比例。
- 扩张、过度扩张、收缩和低谷允许持续数年；过度投放进入未利用运力，不会虚构成真实旅客。
- 五类客群按配置化偏好分配投放能力；单类可承接量不超过单类潜在需求，最终承接量不超过可承接供给。
- 机场容量不足时，在已形成的五类供给结构上压缩；季度经营和预测审计真值读取同一权威城市结果，不再各自重算。
- 北京继续使用双枢纽供给模板并做有限城市微调，其它城市默认使用共享模板。

## 4. 审计、缓存与兼容

- 新增只读客流审计工具 [`tools/audit_passenger_demand.py`](../../tools/audit_passenger_demand.py)，检查区域参考量、城市总分项、offered/serviceable/served 会计、长期满足率、瓶颈和边界分布。
- 固定 Seed、长周期、极端输入、不同发展风格、航司动态场景、季度守恒和 API 序列化均有契约测试。
- 旧 Seed 缓存通过既有 `seed-explorer-run-cache-v4` 内容指纹失效，不需要修改缓存协议号。
- 输出协议仍为 v5；新增口径在既有结构中明确含义，不引入区域—城市总量硬对账，也不伪造 47 城全覆盖。

## 5. 明确未改变

- 没有增加机场对机场航线网络、航空公司主体、机队机型、票价舱位或中转旅客行程计数。
- 没有把区域参考百万人次恢复为城市硬上限。
- 没有为 47 城全部建立完整经营配置；北京仍是季度经营和财务样板。
- 没有在本版本重构资产价格、分红、总回报或区域估值。
- 没有把开发 Run、缓存、Viewer Release 或玩家存档纳入 Git。
