# Airport Game Overview

这是一款围绕机场集团经营、城市航空命运和市场预期展开的长周期经营模拟游戏。

玩家不是只在一个机场里摆设施，而是在一个会变化的世界里经营机场资产：宏观经济会周期波动，区域航空需求会扩张或受压，城市潜在客流会因不同 seed 出现长期分化，机场容量、航司供给、债务、税务、商业合同和估值预期会共同决定一家机场集团能不能活得好。

## 一句话

```text
在不确定的宏观世界里，判断哪些城市值得押注，安排机场扩建和融资节奏，把潜在客流变成真实吞吐、现金流和资产价值。
```

## 玩家在做什么

玩家的核心决策不是“哪个城市现实中更强”，而是：

- 这个 seed 下，哪些城市未来真的有航空盘子。
- 公开共识是不是低估或高估了某个城市。
- 什么时候扩建航站楼槽位，扩多大，能不能熬过固定成本和债务压力。
- 航司供给和机场容量哪个才是真正瓶颈。
- 商业合同、免税、奢侈品和自营零售应该基于什么客流预期签。
- 账面净资产、债务、现金和经营质量如何影响公司价值。

游戏的长期乐趣来自“预期差”：

```text
真实未来
  不直接摆在玩家眼前。

公开共识
  会影响市场、交易、融资和对手判断，但可能很蠢。

玩家预测
  取决于研究水平、情报能力和报告质量。

经营执行
  决定你能不能把看对的未来变成现金流。
```

## 当前主链条

当前代码已经可以一键跑出完整宏观到北京经营样板的路径：

```text
seed
  -> 全球宏观反馈链
  -> 全球历史分岔风险
  -> 14 区区域宏观
  -> 区域 GDP 对账
  -> 区域航空需求
  -> 区域航空供给 / 满足率
  -> 中国大陆 47 城市机场潜在客流与航司供给
       ├-> 北京有效客流预测报告（玩家信息）
       └-> 北京季度经营（真实城市输入）
             -> 北京财务状态 / 资产负债表
             -> 北京净资产主估值与实验市场估值观察
```

## 已经做出来的东西

### 全球和区域宏观

已实现全球 GDP、通胀、政策利率、收益率曲线、美元流动性、信用利差、资产价格、油价和反馈校准。

全球层会生成宏观状态和历史分岔风险，例如虚假黎明、政策失误、信用事故、美元挤兑、能源冲击、流动性泡沫、再融资墙、滞胀和软着陆等。发生路径会重新传导到区域宏观，而不是只贴一个事件标签。

区域层已覆盖 14 个区域，并做了 GDP 体量、占比、排名、增长贡献和对账。

### 区域航空需求和供给

已实现 14 区航空需求层和航空供给/满足率层。

区域航空需求拆成五类旅客：

```text
business
leisure
vfr
long_haul
transfer
```

区域航空供给层回答：

```text
想飞的人里，有多少能被航司运力服务？
```

这让城市机场不是凭空吞吐客流，而是先受到航司座位、航线、交付、人员和机场时刻环境约束。

### 中国大陆 47 城市机场市场

中国大陆 47 个城市机场市场已经有可运行配置，并全部启用 seed 城市航空势能模板。

城市层回答：

```text
这个城市未来有多少潜在航空需求？
航司能服务多少？
机场系统能吞吐多少？
瓶颈是在需求、航司供给还是机场容量？
```

城市潜在客流不是简单复刻现实强弱。同一个 seed 下，北京、上海、广州、深圳、成都、重庆、杭州、西安、武汉、青岛、乌鲁木齐、三亚等城市会在合理边界内出现不同长期命运。

这让玩家不能只背现实排名，而要根据本局世界线判断哪里值得扩建。

### 设施槽位和容量

机场扩建采用离散槽位制，而不是连续加容量。

标准设施规格：

```text
small
medium
large
extra_large
giant
```

每个设施有设计容量和极限容量。低于设计容量时经营舒适；超过设计容量但未超过极限容量时仍能运行，但拥挤、成本、服务质量和商业效率会恶化。

北京样板已经有首都 + 大兴双机场槽位结构。

玩家界面中槽位优先显示为 `主槽位`、`次槽位`、`辅助槽位1/2/3`。`PEK_SLOT_1`、`PKX_SLOT_2` 这类 `slot_id` 是内部配置和调试口径，不应直接作为面向玩家的名称。

经营报告已经加入服务质量观察：感知质量指数、质量拆解、容量舒适度、商业影响乘数，以及航站楼维护状况。维护状况按运营槽位解释状态、等效维护年龄、维护来源和维护年龄分，用来说明老化、翻新、拆除重建和新建如何影响旅客体验，而不是只展示一个汇总扣分。

### 有效客流预测系统

北京已经实现第一版有效客流预测报告。

预测系统的主对象不再是单纯潜在客流，而是市场有效客流：

```text
市场有效客流 = min(城市潜在客流, 航司供给)
```

这样预测报告更接近玩家真正要下注的市场机会：有需求但没航司供给，不会自动变成机场收入；航司供给充足但需求不足，也不能凭空创造客流。

预测不是直接展示真实未来，而是分别把隐藏真实潜在客流和航司供给降质成玩家可见报告，再取小值得到有效客流预测：

```text
隐藏真实潜在客流 / 航司供给
  -> 初级 / 中级 / 高级 / 专业级预测
  -> 有效客流中值、区间、可信度、滞后、seed 捕捉率和解释标签
```

当前五档：

| 报告 | 分数 | 含义 |
|---|---:|---|
| `public_consensus` | 18-50 | 初级预测，来源为公开共识，市场默认口径，可能准确，也可能套人 |
| `basic_research` | 25 | 中级预测 |
| `professional_consulting` | 48 | 高级预测 |
| `top_institution` | 70 | 专业级预测，普通预测上限 |
| `god_future_peek` | 100 | 神级未来透视，明确开挂 / 调试模式 |

普通预测只在 0-70 分内变化。分数越高，中心值通常更接近真实曲线，滞后越短，seed 捕捉更强；年限越远，所有普通预测都会变得更不可靠。公开共识不是固定低分来源，它有时能达到 40-50 分水平。可见区间宽度不再直接等于报告质量：共识也可能显得很自信，但它可能只是自信地错。

机构报告采用短中期连续预测窗口，不把 30 年年度预测包装成严肃市场研究：初级 6 年，中级 8 年，高级 10 年，专业级 12 年。更长的全周期曲线只属于神级未来透视、沙盒或调试模式。

神级预测不是更准的普通模型，而是 `future_peek_mode = true`，直接看隐藏真实曲线。

预测报告还会输出五类分项预测：商务、休闲、探亲访友、长途和中转。分项不是五条独立乱飞的预测曲线，而是在总有效客流预测上拆分结构；结构误差受报告质量、预测瓶颈、年限和分项不确定性影响。中转、长途更难预测，商务、休闲相对稳定。

预测报告还会在输出后生成 `realized_report_quality_score`。这个分数是拿报告曲线和隐藏真实 seed 曲线事后对比得出的 0-100 审计分，不等于报告等级。初级报告可能在 6 年窗口内蒙对并拿高分，专业级报告也可能在 12 年窗口内因为偏乐观、偏悲观、瓶颈错判或分项结构错误而失分。

### 北京季度经营

北京样板已经能从城市客流进入季度经营。

经营层已经包括：

- 航空性收入。
- 客流变动成本。
- 餐饮零售自营收入和成本。
- 免税合同收入。
- 奢侈品 / 精品合同收入。
- 固定经营成本。
- 拥挤成本。
- 季节性季度分布。

2025-2029 是玩家不能操作的开局历史期。该阶段的免税和奢侈品合同仍视为开局前已签署，但北京样板会先读取这段历史期的实际模拟销售额，反推一份合理的历史期保底基准，而不是只使用固定写死的基准收入。只读回放继续展示自动续约结果；模拟运营则允许玩家在谈判窗口内确认服务端给出的下一期建议条款，逾期时按当前建议条款自动续签。

动态测试已把“加载历史”和“模拟运营”分开。前者读取完整、只读的既有结果；后者以同一 seed 的 2025-2029 开局历史为背景，从 2030 Q1 起只保存当前季度和玩家行动日志。合同、项目或融资行动确认后，服务端会把行动写入本局专用配置，并从同一套经营层和财务状态层重算；浏览器只负责展示返回的季度结果，不再用自己的合同收入、税务、现金或资产负债表公式充当账本。完整季度结果会随模拟局首次建立或行动变化而生成，日常前后翻季直接在已加载的结果中切换；服务端还会按行动日志哈希复用未变化的结果，避免反复写盘和重跑。存档不复制长期报表，并已独立保存在 `saves/seed_explorer/`；清理或强制重算 `output/seed_explorer_runs/` 中的临时缓存不会删除玩家存档。

模拟运营的合同事务 v0.1 与经营报告并列，用来提示合同到期、展示下一期建议条款，并允许玩家在到期前 4 个季度内确认签署；到期前最后 1 个季度必须确认，若玩家仍未确认，系统会按当前建议条款续签。当前仍只有“确认建议条款”，还不是完整的合作方竞标、报价选择或谈判系统。

融资事务与合同、项目事务并列。玩家每季最多可发起一笔短期周转、长期建设或宽限期建设贷款，选择融资额和标准期限；服务端将其写入一般贷款账本，在提款季按宏观基准、贷款类型、城市信用环境、资产负债率和期限利差锁定利率，并继续计算付息、还本、余额与拒贷。期限会直接影响报价：短期周转 4/8/12 季分别增加 0/15/30bp，长期建设 40/60/80 季分别增加 0/20/45bp，宽限期建设还叠加宽限期利差。资产负债率低于 45% 时不加杠杆利差，45%-80% 区间按连续规则上升；提款前或提款后达到 80% 时本季拒绝提款，也不生成“可贷利率”。融资事务只展示操作和当前摘要，详细台账与逐笔融资事件仍统一在经营报告的债务与融资中查看。

模拟运营的项目事务 v0.1 同样使用行动日志和服务端季度重算。玩家先按槽位查看方案：已投运槽位可以翻新或拆除重建，空槽位可以新建。候选方案不会进入项目或资产台账；只有确认当前季度开工，才会生成真实工程。翻新会形成独立翻新资产并改善维护年龄；新建完成后会把新槽位加入有效容量；拆除重建会分别记录资本化支出、拆除费用和旧资产减记。经营报告中的客流容量、服务质量、工程/资产台账和财务分析会读取同一套重算结果。

翻新按可重复的工程实例处理：同一槽位施工窗口不能重叠，翻新完工后需冷却 6 年（24 季）才可再次发起。项目事务只保留当前施工中的工程；完工工程转入项目台账，形成的资产持续保留在资产台账。原航站楼不带后缀，后续翻新资产按发生顺序命名为 `航站楼名-2`、`航站楼名-3` 等；重复的工程名称允许存在，由开工和完工时间以及内部项目 ID 区分。

拆除重建同样按工程实例处理。玩家可从槽位角色允许的非空航站楼等级中选择目标规格；启动要求同槽位没有施工且当前季度现金不为负，确认后不可取消。施工期槽位容量归零，维护年龄及其感知质量贡献不参与计算；完工后维护年龄重置为 0 年，并形成新的重建资产。工期和造价都由两段组成：按原规格计算的拆除工期与拆除费用，加上按目标规格计算的新建工期与资本化支出。因此“大型拆除后重建为超大型”和“超大型原规格重建”会有不同的工期和资金压力。重建完工后冷却 20 年（80 季）才可再次发起；重建完成后也需等待 6 年（24 季）才可翻新。

拆除是和拆除重建并列的独立工程。它按拆前航站楼规格计算工期和拆除费用，施工期关闭槽位并核销旧资产，但不形成新资产；完工后槽位回归空白，再经过 1 年（4 季）清场期才可重新新建。槽位的基础 `Tn` 编号不会回收或改变，因此拆除 `首都T4航站楼` 后在同一槽位再次新建仍默认命名为 `首都T4航站楼`。

新建只可用于空槽位。玩家从该槽位角色允许的规格中选择目标；确认时服务端冻结工期、资本化支出和新资产折旧参数，施工期不会增加既有容量或参与维护质量，完工后才投运。完工槽位从此作为常驻航站楼处理，可改名、翻新和拆除重建，已完成的新建方案则从项目事务中撤下，仅保留在台账。默认名称按机场独立顺序编号，且不受玩家改名影响：首都机场已有 T2/T3 后依次生成 `首都T4航站楼`、`首都T5航站楼`，大兴机场已有 T1 后依次生成 `大兴T2航站楼`、`大兴T3航站楼`。新建完成后同样需等待 6 年（24 季）才能翻新；建成航站楼可再由玩家改名。

这让扩建不再只是“容量越大越好”。提前扩建会增加固定成本、折旧和融资压力；扩晚了会造成拥挤、未满足需求和商业效率损失。

### 当前经营闭环

当前北京样板已形成可操作的最小闭环：全球与区域宏观驱动城市潜在客流和航司供给，有效需求进入机场季度经营；容量、施工、维护年龄和感知质量影响承接与商业表现；合同决定免税与精品收入规则；项目和融资动作再回流到容量、固定资产、现金、利息、税务、债务与经营报告。它仍是北京单城的动态测试环境，但不再只是读取静态剧本。

### 财务、贷款、税务和估值

北京财务状态层已经接上：

- 资产负债表。
- 现金。
- 固定资产和在建工程。
- 折旧。
- 一般贷款。
- 利息和还本。
- 资产负债率约束。
- 25% 企业所得税。
- 季度预缴、Q4 年度汇算。
- 5 年亏损结转。

估值当前采用稳定的净资产主口径：

```text
主股权价值 = 账面所有者权益
主企业价值 = 主股权价值 + 净债务
P/B ~= 1.0x
```

DCF、市场 EV、PE/PB、宏观市场折溢价等仍保留为观察指标，不作为当前单人阶段的主定价。原因是预测、合同、资本配置和城市横向比较还在成长中，估值系统不应该过早显得比上游更聪明。

## 当前最有特色的机制

### 信息不是免费真理

游戏不直接告诉玩家未来。玩家看到的是不同质量的预测报告。

公开共识可能只是现实排名和近期趋势的外推，但它会影响市场定价和对手行为。高级预测更接近真实世界线，但仍不是剧透。神级预测则明确是开挂。

### 城市命运会变，但不乱变

不同 seed 下，城市航空体量曲线会变化。成都可能更强，重庆可能更强，青岛可能冲到更高层级，乌鲁木齐或三亚可能在某些世界里更值得关注。

但系统仍保留现实结构和区域宏观相关性，不会让小城市无理由变成全球第一。

### 看对未来不等于自动赢

即使玩家知道某城市远期会强，也可能因为：

- 扩建过早导致现金流断裂。
- 航司供给跟不上。
- 债务期限错配。
- 固定成本太重。
- 合同签得太保守或太激进。
- 市场共识暂时不买账。

而无法把潜在客流变成真实利润。

## 当前边界

目前已经相对完整的是“宏观 -> 区域航空 -> 中国大陆城市潜在客流/航司供给”，随后分成两条北京样板分支：一条生成玩家可见的有效客流预测，另一条把真实城市输入送入季度经营、财务和估值观察。预测报告本身不决定实际经营结果。

尚未完成：

- 其它城市的季度经营和财务配置。
- 合同合作方、报价选择和谈判博弈；当前只有建议条款确认与到期处理。
- 独立商业销售预测；当前合同签署闭环仍主要读取既有经营输入和服务端建议条款。
- 商业情报中心、研究所和对手预测模型。
- 正式市场交易、并购和股权市场。
- 全球其它城市机场配置。

## 当前入口

一键生成完整 run：

```powershell
py -3 .\macro_layers\macro_run_orchestrator_sim.py --random-seed
```

固定 seed：

```powershell
py -3 .\macro_layers\macro_run_orchestrator_sim.py --seed 20261324 --scenario-state none
```

生成并发布到 viewer：

```powershell
py -3 .\macro_layers\macro_run_orchestrator_sim.py --seed 20261324 --scenario-state none --publish-viewer baseline
```

主要界面：

```text
start_airport_ui.bat
http://127.0.0.1:8776/
```

也可以从 `airport` 根目录跨平台启动：

```powershell
python -m airport_ui
```

统一首页可以进入 Seed 动态测试、全球宏观、北京机场经营和有效客流预测。五个页面与静态资源分别位于 `web/pages/`、`web/static/`，正式本地服务位于 `airport_sim/server/app.py`；这些源码归位不改变浏览器地址。旧的 `dynamic_tests/seed_explorer/start_seed_explorer.bat` 仍可使用，但现在会调用统一服务并直接打开动态测试页。

如果需要了解页面、Python 后端、正式 Run、Viewer 发布、缓存和存档之间的区别，请先阅读 `Current_Architecture_and_Runtime.md`。

## 未来方向

短期最自然的下一步：

1. 为合同加入合作方、报价选择与谈判过程，让签约不再只是确认建议条款。
2. 让项目方案、合同条款和融资条件能够在行动前做统一测算与比较。
3. 明确自营商业预测边界：除客流预测外，短期先读取公开自营盘预算参数。
4. 独立商业销售预测，用于免税和奢侈品合同。
5. 让合同报价读取玩家可见预测，而不是偷看真实未来。
6. 扩展更多城市的季度经营、项目、合同和融资配置。

中后期可以发展为：

- 研究所：提高自己的真实预测能力。
- 商业情报中心：获取对手报告和市场共识偏差。
- 市场共识：影响资产交易和融资。
- 并购和资产出售：围绕预期差定价。
- 多人或 AI 对手：利用信息差、现金流和扩建节奏互相博弈。
