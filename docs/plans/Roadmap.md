# 项目路线图

这份文档只保留尚未完成、仍有明确收益的工作。已经完成的拆分、迁移和清理记录由 Git、[v0719 Preview2 交接说明](../releases/v0719-preview2.md)和[上一阶段交接说明](../releases/v0719-preview.md)保存，不再作为未来任务重复执行。

## 1. 当前基线

- Python 3.13 是唯一支持版本，统一命令和 8776 服务入口位于 `airport_sim`。
- 公开兼容期已经结束：页面只保留五个正式短地址，存档只使用 `/api/sim-save`，API Schema 已升级为 `seed-explorer-api-v2`。
- 全球、城市和预测 Viewer 已使用版本化 Release、轻量索引与按需分块；Release 默认保留当前版和最近一个备份版。
- 版本化资源支持流式响应、SHA-256 ETag、长期 immutable 缓存和发布期 gzip。
- 59 份正式 JSON 已归入 13 个配置族，并有结构、范围、引用、权重和时间线校验。
- 服务端路由、API 契约、Run/缓存、玩家行动、合同、项目、融资、北京经营和工作区状态已有独立模块；`app.py` 主要保留兼容装配和进程入口。
- 宏观编排器的发布、索引、资产、校验、变体写入和 Run 生命周期已有独立模块；剩余主体涉及模型执行和随机数语义，不再做机械拆分。
- Run、缓存、Viewer 发布和玩家存档相互分离；关键 API、缓存与存档对象已有 Schema。
- 北京是唯一具备完整动态经营闭环的城市；估值仍是实验观察，不是成熟游戏功能。

## 2. 输出空间：本阶段完成，后续按需

2026-07-19 已完成正式 Run 单版本收敛与 canonical 消费者审计：删除 9 个旧 Run，并停止生成、清理 257 个无消费者 canonical 副本。`output/` 从 2,508,242,055 字节降至 756,574,236 字节；只保留当前 Viewer 的完整源 Run `forecast_v12_closeout_20260718`，两个 Viewer Release、Seed Explorer 缓存及玩家存档均保持不变。详细保护项与验证结果见 [v0719 Preview 交接说明](../releases/v0719-preview.md)。

后续触发条件：

1. 正式 Run 自动保留数量等正式存档机制明确后再设计，当前不固化。
2. 只有 `output/` 再次明显增长时才重新测量精确重复，并从新基线开始。
3. 只有剩余重复长期显著时，才比较 Windows 硬链接或内容寻址；当前不引入 SQLite、Parquet 或数据库。

正式 Run 不承载玩家存档，但保留策略仍不应在模型运行时静默删除历史产物；继续使用可预览、显式确认的清理流程。旧 Run 可用相同代码版本与 Seed 重建。

## 3. 后续：统一经营界面前的信息隔离（暂不急）

未来的正式机场经营界面会把经营总览、预测、合同/项目/融资和季度推进放到同一玩家流程中。在开始合并页面前，应消除 Seed Explorer 对真实未来的暴露；当前尚无正式存档和统一界面发布需求，因此暂不阻塞存储空间治理。

下一任务集群：

1. 盘点所有包含 `allQuarters`、未来合同结果或隐藏预测真值的 API 响应。
2. 为正式玩家接口只返回当前季度可见历史和必要摘要，开发审计接口继续独立存在。
3. 明确预测报告的按需加载、缓存和失效规则。
4. 为独立预测页和开发审计入口定义正式产品中的去留与权限边界。
5. 用固定 Seed、真实浏览器和 API Schema 验证信息边界，不改变模型计算结果。

完成后才能开始统一展示与导航。界面合并本身仍遵循“先组织现有功能，不顺便修改公式”的原则。

## 4. 第三优先：协议与安全小收尾

这些任务有价值，但不应阻塞前两项：

- 部分旧 GET 错误仍没有 `errorCode`；优先描述现状并补特征测试，格式统一可以后做，不能破坏现有客户端。
- 全球 Viewer 动态脚本仍有内联 `onerror`；清除后再评估内容安全策略（CSP）。
- 只有出现第三种稳定运行语义时才引入命名 Run Profile；当前 `full` 与 `seed-cache` 已足够。
- 只对审计确认仍会直接覆盖的权威单层输出补原子写入，不为临时文件增加复杂生命周期。
- 公开的旧包、直接脚本和 URL/API 别名已经退役；以后只在修改相关模块时收敛 `app.py` 与宏观编排器内部的兼容门面，不为消除内部转发层单独发动大规模改写。

## 5. 产品与模型的独立方向

以下事项需要独立设计和验收，不能混入机械重构：

- 为合同增加合作方、报价比较与谈判过程。
- 让项目方案、合同条款和融资条件在确认前按同一口径测算。
- 明确自营商业预算边界，并另行设计免税、奢侈品等销售预测。
- 让合同报价只使用玩家可见预测，不读取隐藏真实未来。
- 完善报告获取成本、质量和预测—实际对照机制。
- 北京闭环稳定后，按[北京样板与新增完整经营城市指南](../reference/Beijing_Template_and_New_City_Guide.md)评估新增经营城市。
- 重新定义估值的用途、输入和反馈后，再把它升级为正式系统。

涉及公式、参数、随机数消费或浮点顺序的变化必须升级模型版本，并建立新的固定 Seed 预期，不能以“重构”名义修改现有结果。

## 6. 明确暂缓

- 季度经营主函数拆分：风险高，当前没有功能需求支撑，不为降低行数而移动公式。
- 浏览器宏观近似模型重写：先决定它是非权威预览、数值等价实现还是服务端权威模型的客户端。
- 区域与城市并行：需先证明模型计算是瓶颈，并保证跨平台随机数、浮点和汇总顺序一致。
- 玩家行动增量重算：需先有版本化季度状态快照、恢复接口和全量/增量逐行等价测试。
- Brotli、数据库或 Parquet：现有 gzip、分块和保留策略不足时再评估。
- 研究所、资产交易、多人或 AI 对手：形成规则、数据边界和验收标准后再排期。

## 7. 共同完成标准

一个任务集群只有在以下条件都满足时才算完成：

- Python 3.13 完整测试通过，固定 Seed 数值没有无意变化。
- API、Schema、前端、缓存指纹和文档同步。
- Run、缓存、Viewer 发布和存档边界没有混淆。
- 涉及 UI 时完成真实浏览器验收和信息可见性检查。
- 涉及输出清理时先生成只读计划，验证目标位于 `output/` 内，并记录可恢复性。
- 兼容入口有明确保留或退出结论。
- Roadmap 只记录未完成事项；实施流水由提交和专题交接说明保存。
