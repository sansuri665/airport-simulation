## 2. 本阶段已经完成

### 输出与 Viewer 生命周期

- CI 增加 Markdown 本地链接和浏览器 JavaScript 语法检查，并固定 Node.js 运行环境。
- Viewer Release 默认只保留当前版和最近一个有效备份版；Manifest 无效、存在 staging 或服务运行时，破坏性清理继续失败关闭。
- 一次获准的安全清理删除 12 个过期 Viewer Release 和 1 个历史验证 Run，命令报告释放 917,086,051 字节。
- `output/` 从 3,419,608,923 字节降至 2,502,520,249 字节；正式 Run 的人工审查项未被自动删除。
- 文件响应改为 64 KiB 流式发送，支持 SHA-256 ETag、`304`、按资源类型设置缓存策略，以及发布期确定性 gzip 旁车。
- 全球 Viewer 已退出浏览器端旧逐脚本/CSV 回退，与城市和预测 Viewer 一样使用版本化 Release、轻量索引与按需分块。

### 配置与数据协议

- 59 份正式 JSON 已归入 13 个配置族，`validate-config` 会检查结构、范围、ID、跨文件引用、适用的权重守恒、曲线顺序和跨层时间线。

- 校验错误稳定包含文件路径、错误代码、JSON 位置和可读消息；测试与运行时共用同一 Schema 实现。

### 服务端与宏观编排器边界

- 服务端公开路由、API Schema、Run/缓存、玩家模拟、行动日志、合同、项目、融资、北京经营、预测候选和工作区摘要已迁入独立模块。
- `airport_sim/server/app.py` 从约 2,615 行降至 978 行，剩余内容主要是兼容包装、共享常量和进程入口；不再为降低行数继续机械拆分。
- 宏观编排器的 Viewer 发布、Run 索引、资产协议、Run 校验、变体产物和顶层生命周期已迁入六个独立模块。

## 5. 输出空间的剩余事实

当前 `output/` 中约 76% 来自 `macro_runs/`。现存 10 个正式宏观 Run 中，多次 Seed 424242 运行合计约 1.25 GB，但它们可能承担不同验证目的，不能只凭名称自动删除。

只读 SHA-256 盘点发现 424 组精确重复，理论重复逻辑字节约 1.28 GB；其中大量跨越 canonical、Run 与 Viewer Release。这个数字不是可直接释放空间，因为：

- 部分副本是正式归档或当前发布协议所需；
- 当前大文件尚未使用硬链接；
- 删除历史 Run 和停止 legacy canonical 后，重复结构会变化；
- Windows 备份、跨卷复制和恢复流程尚未验证内容寻址或硬链接方案。

因此下一步应先人工复核 Run、确认 legacy canonical 消费者并重新测量，再决定是否做去重实验。不要仅凭这次理论值直接修改产物布局。

## 6. 建议的后续顺序

1. 收紧 Seed Explorer 与玩家接口的未来信息可见性，尤其是 `allQuarters`，为统一经营界面建立安全边界。
2. 人工复核正式 Run，盘点已无消费者的 legacy canonical；经单独确认后清理并重新测量空间。
3. 只有剩余精确重复仍显著时，做硬链接或内容寻址的隔离实验。
4. 完成旧错误响应、内联脚本/CSP 和必要原子写入等低风险协议收尾。
5. 再进入统一经营界面；季度模型拆分、浏览器近似模型、并行化和增量重算继续暂缓。

## 7. 后续维护约束

- 任何模型公式、配置值、随机数消费或浮点顺序变化都应升级模型版本，不能混入结构重构。
- 不把 Preview2 的测试通过解释为允许自动合并 `main`。
- 不在没有只读计划和人工确认时删除正式 Run、当前 Release 或玩家存档。
- 新的完成记录优先写入提交与稳定专题文档；本交接说明只在 Preview2 边界或关键事实发生变化时更新。
