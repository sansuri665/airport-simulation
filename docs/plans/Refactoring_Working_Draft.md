## 5. 输出空间的剩余事实

本轮开始前 `output/` 为 2,508,242,055 字节，其中 `macro_runs/` 为 1,898,501,712 字节，约占 76%。现存 10 个正式宏观 Run 都是可重建的模型产物；它们不承载玩家正式存档，玩家状态另存于 `saves/`，Seed Explorer 缓存也有独立生命周期。

项目已经作出新的保留决定：当前没有需要长期保存的正式游戏进度，正式宏观 Run 只保留最新且完整的 `forecast_v12_closeout_20260718`。2026-07-19 已在停止服务、校验绝对路径与重解析点之后删除其余 9 个旧 Run；这些目录包含 2,984 个文件、合计 1,672,192,269 字节。随后 Run 索引从 10 条重建为 1 条。

索引文件同时缩小了 23,337 字节，因此 `output/` 实际从 2,508,242,055 字节降至 836,026,449 字节，总计减少 1,672,215,606 字节，约 66.7%。清理后的 `macro_runs/` 为 226,286,106 字节，只剩 `forecast_v12_closeout_20260718`。

Run 清理没有删除以下内容：

- 当前和最近一个备份 Viewer Release；
- canonical 输出与 Viewer 当前指针；
- Seed Explorer 缓存；
- `saves/` 下的玩家存档与行动日志。

备份 Viewer Release 自身是完整发布产物，即使对应旧 Run 被删除仍可继续读取；只是以后若要从源 Run 重新发布，需要用相同版本与 Seed 重新运行。当前 Viewer Release 的源 Run 正是保留项 `forecast_v12_closeout_20260718`。

删除前后保护项对照一致：两个 Viewer Release 仍为 180 个文件、323,009,743 字节；Seed Explorer 缓存仍为 207 个文件、41,740,673 字节；`saves/` 的 3 个文件大小与 SHA-256 均未变化。8776 服务恢复为 PID 38280，首页、三个 Viewer、当前 Manifest、Run 索引和当前 Release bundle 均返回 HTTP 200；相关 53 项单元测试通过。

随后完成了 10 个发布相关 canonical 目录的文件级消费者审计。现存 393 个文件中，136 个仍有明确用途：全球/预测无 Manifest 回退，或独立模型命令的下游 CSV；其余 257 个旧摘要、旧 Viewer 脚本、诊断/图形副本和完整预测 CSV 没有读取者。发布器已改用白名单，不再生成这些无消费者副本；现存文件经路径校验后删除，释放 79,452,213 字节。

canonical 收敛后 `output/` 进一步从 836,026,449 字节降至 756,574,236 字节。两次清理累计减少 1,751,667,819 字节，约 69.8%。Run、两个 Viewer Release、Seed Explorer 缓存和 3 个存档哈希仍保持不变；正常 Release 页面以及全球/预测 canonical 回退的索引、主脚本和样例分块均返回 HTTP 200。Python 3.13 完整回归为 302 项通过。

只读 SHA-256 盘点发现 424 组精确重复，理论重复逻辑字节约 1.28 GB；其中大量跨越 canonical、Run 与 Viewer Release。这个数字不是可直接释放空间，因为：

- 部分副本是正式归档或当前发布协议所需；
- 当前大文件尚未使用硬链接；
- 删除历史 Run 和停止 legacy canonical 后，重复结构会变化；
- Windows 备份、跨卷复制和恢复流程尚未验证内容寻址或硬链接方案。

旧盘点已被本轮删除显著改变，不能继续用 1.28 GB 推算收益。硬链接或内容寻址只有在清理后重新盘点仍发现显著、稳定、不可变的重复时才值得实验。

## 6. 建议的后续顺序

1. 正式 Run 自动保留与存档机制一起设计；当前不提前固化“保留 1 个”的代码策略。
2. 目前 `output/` 已低于 0.76 GB，不再主动做硬链接、内容寻址或数据库改造；只有空间再次明显增长时才重新盘点。
3. 正式游戏的信息可见性边界与统一经营界面暂缓，等产品流程需要时再处理。
4. 季度模型拆分、浏览器近似模型、并行化和增量重算继续暂缓。

以下事项有价值但不急，可在相关代码再次修改时顺手完成：

- **兼容错误响应**：部分旧 GET 错误仍只有 `ok` 与 `error`，没有 `errorCode`；先按 [API 与数据契约](../reference/API_and_Data_Contracts.md)补特征测试，再决定是否统一，避免破坏旧客户端。
- **CSP 收尾**：当前主要已知障碍是全球 Viewer 启动脚本中的内联 `onerror`；本地服务风险较低，移除动态内联错误处理后再启用或收紧 CSP。
